## Completed implementation stages

1. **Android foundation and security boundary:** Compose/Material 3, English/Greek resources, Keystore-backed encrypted storage, typed actions, deny-first observation/mutation policy, exact approvals, expiring grants and strict plan-only enforcement.
2. **Real device tools and practice workflow:** filtered Accessibility trees, stale/window/focus/rotation binding, semantic/coordinate gestures, ordinary text, app launch/navigation, screenshots, bounded waits and a deterministic provider controlling a separate bilingual fixture app.
3. **Authentication and providers:** own-client ChatGPT browser registration/sign-in, loopback callback, PKCE/state/nonce, identity signature/claims verification, refresh/logout, model discovery, streamed Responses with namespaced function tools; separate OpenAI-key and compatible/local profiles with origin-bound secrets.
4. **Everyday UI and recovery:** task states, streaming, action summaries, checklist, questions/corrections, Pause/Resume/Stop, ongoing notification controls (the former floating bar was removed in 0.1.4), attachments and Android entry points; encrypted searchable history, branching/deletion/retention, explicit interruption recovery, encrypted backup/import and diagnostics previews.
5. **Scripts and extensions:** finite typed JSON scripts with hard limits and no ambient code execution; app-scoped reviewed memory/playbooks; optional, consented MCP Streamable HTTP with schema fingerprints, bounded transport and central policy enforcement.
6. **Verification and release preparation:** security/protocol regression suites, dedicated emulator instrumentation, debug/unsigned release builds, release manifest/resource checks, pinned CI, dependency locks/checksums, license inventory and contributor/security/privacy/architecture documentation.

## Consequential decisions

- `minSdk=30`, `targetSdk=36`, `compileSdk=37`; current Compose requires compilation against SDK 37.0. Target 36 is deliberate and does not assert store approval. JDK 21, Gradle 9.4.1 and AGP 9.2.1 are pinned.
- Three modules: Android app, pure Kotlin core and the isolated Android fixture. No computer, root, ADB or developer backend is required for normal app use. SSH/ADB are development/test tools only.
- A finite JSON instruction language replaces a general Lua VM. At most 40 steps, 12 bounded parameters, 64 KB source and a 120-second deadline; no loops, exception handling, shell, network, files, reflection or dynamic loading.
- Observation and mutation have separate app permissions. Every device operation, batch substep, script operation and MCP call passes through `Gateway`. Own/system security interfaces are protected.
- Unknown overlays, mixed windows and detected password screens fail closed. Screenshot cropping excludes system bars and rejects empty intersections. This cannot detect every sensitive custom UI; the threat model explains the limitation.
- Screenshots and attachments stay transient. Persistence stores sanitized conversation content and payload-free operation/status audit records. Backups contain no credentials, endpoints or policies and cannot activate imported scripts/notes.
- Android Accessibility is a bound service; the app does not invent an unsupported foreground-service type. OS process death requires explicit user continuation and never replays external actions.
- The supported ChatGPT OSS flow was checked against official documentation. Protocol tests use controlled servers; they are explicitly separate from account-owner consent and live inference.
